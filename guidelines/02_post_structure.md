# 02. 포스트 표준 구조

검색 유입을 위한 SEO와 가독성을 동시에 만족시키는 포스트 표준 구조입니다.
카테고리별 세부 템플릿(`templates/`)은 이 골격을 변형한 것입니다.

## 0. 시각적 리듬 (가장 중요)

> **표준 레퍼런스 (2개)**
> - (1차) `drafts/20260509_food_konkuk_goheungsoondae_FOR_TISTORY.md` → 발행 https://marcoaeolus.tistory.com/889 (2026-05-09)
> - (2차) `drafts/20260414_food_yeonnam_mugen-switch_FOR_TISTORY.md` → 발행 https://marcoaeolus.tistory.com/890 (2026-05-24) ← **현재 최신 기준**
> 박민재 님 확정 — "이런 글 형태로 계속 나오면 좋겠어"

이 블로그 글의 정체성은 **사진 비중 > 글 비중**의 비주얼 리듬이다. 다음 룰을 깨면 글의 결이 무너진다.

- 사진 8~15장. 카테고리에 따라 권장치는 다르지만 **글보다 사진이 항상 시각적으로 우세**해야 한다.
- 한 단락 1~3문장. 길어지면 사진을 더 추가해서 분산한다.
- 사진 사이 캡션은 짧은 한두 줄. 정보형 단락은 사진 묶음 사이에 따로 배치.
- ◈ 정보 박스는 본문 시작 직후 1회만. **형식은 `>` 블록쿼트로** (표 아님):
  ```
  > ◈ **상호명**
  > 위치 : 도로명 주소
  > 영업시간 : ...
  > 교통 : ...
  > *특이사항 (주차불가, 키오스크 등)
  ```
- **배경 지식 섹션 (선택)**: 독자에게 생소한 음식/장르/카테고리일 때, 도입부 + 정보박스 직후에 H2 섹션으로 짧게 설명. 예: `## 이에케(家系) 라멘이란?` — 아는 사람이 많을 때는 생략.
- **제목 부제(`— 부제`)는 권장하지 않음**. 발행 제목은 `[지역] 설명 '상호명'` 형태로 간결하게. 부제는 메타 디스크립션으로 이동.
- 마무리 블록은 항상 동일 구성: 좋았던 점 / 아쉬웠던 점 / 추천 대상 / ★/5 별점 + 한 줄.
- 본문 마지막 줄: `— by Marco`.

## 1. 글의 기본 골격 (4-Block 구조)

```
[1] 도입(훅)        — 100~200자
[2] 핵심 정보 박스   — 표 또는 박스로 한 눈에
[3] 본문(섹션 H2~H3) — 시간/주제 순으로 분할
[4] 마무리·요약     — 한 줄 평 + 다음 글 링크
```

### Block 1. 도입(훅)

- 첫 1~2문장에 **장소/제품/주제명**과 **방문/사용 시점**을 명시한다.
- 독자가 "내가 찾던 글이 맞다"는 확신을 5초 안에 가져야 한다.
- 클릭베이트성 호들갑(❌ "이거 모르면 후회"…) 금지.

> 좋은 예: "지난 주말, 강릉 안목해변에 새로 오픈한 카페 ○○에 다녀왔어요. 평일 4시쯤 방문했고, 자리 잡기는 어렵지 않았습니다."

### Block 2. 핵심 정보 박스

독자가 본문을 안 읽어도 핵심을 가져갈 수 있도록 **표 또는 인용 박스**로 정리.

```
| 항목 | 내용 |
|---|---|
| 위치 | (지번/도로명) |
| 영업시간 | (요일별 차이 명시) |
| 주차 | (가능 여부 + 무료/유료) |
| 가격대 | (1인 기준) |
| 추천 메뉴 | (가격과 함께) |
| 한 줄 평 | (개인 평) |
```

카테고리별로 항목은 변형 (여행은 동선·교통, IT는 스펙·가격 등).

### Block 3. 본문 (H2/H3 섹션)

- **H2는 2~5개**로 분할. 너무 많으면 산만하고 너무 적으면 SEO에 불리.
- 각 H2 아래 단락은 5~8줄.
- **이미지는 H2당 1~3장** 배치. 이미지마다 alt 텍스트 작성.
- 정보형 글일수록 **번호 리스트 / 표** 적극 사용.

### Block 4. 마무리·요약

- "전체적으로 어땠는지" 한 줄 평.
- **재방문 의사 / 추천 대상**을 명시 (맛집·카페·IT 리뷰 공통).
- 관련 이전 글로 가는 **내부 링크 1~2개**.
- 마지막 문장은 가벼운 인사 또는 다음 글 예고.

## 3. 제목 작성 룰

- 30~40자 이내, 한국어 키워드 자연스럽게 포함.
- **[지역/제품] + [핵심 정보] + [톤]** 패턴.
  - 예: "강릉 안목해변 카페 ○○ — 오션뷰 좋지만 주차는 헬"
  - 예: "[제품명] 한 달 사용기, 단점부터 말합니다"
- 클릭베이트형 ("절대 가지 마세요", "충격적인…") 금지.

## 4. 문단·간격 규칙 (마크다운 작성 시 필수)

본문의 시각적 호흡을 일정하게 가져가기 위한 간격 룰. 챕터 안은 한 줄 간격, 챕터 사이는 두 줄 간격.

| 위치 | 간격 (빈 줄) |
|---|---|
| 사진 ↔ 같은 챕터 내 본문 글 | 1 |
| 본문 글 ↔ 본문 글 (단락 구분) | 1 |
| 사진 또는 글 ↔ 다음 H2 챕터 시작 | **2** |
| H2 헤딩 ↔ 그 아래 첫 사진/글 | 1 |

예시:

```
[사진 N — alt: ...]
                          ← 빈 줄 1
이 사진은 무엇을 보여주는지 짧게 한 단락.
                          ← 빈 줄 1
같은 챕터 안의 다음 단락이라면 한 줄만 더.
                          ← 빈 줄 2 (챕터 사이는 두 줄)

## 다음 챕터 제목
                          ← 빈 줄 1
[다음 챕터 첫 사진]
```

티스토리 마크다운 모드는 빈 줄 개수를 보존하므로 위 패턴이 그대로 렌더링된다. 발행 후 모바일 미리보기에서 호흡이 일정한지 한 번 더 점검.

## 5. 부속 요소

- **목차(TOC)**: 1,500자 이상 글에는 무조건 삽입 (티스토리 [목차] 매크로 활용).
- **태그**: 5~10개. 핵심 키워드 + 지역 + 카테고리.
- **카테고리**: 글 하나 = 한 카테고리 (중복 분류 금지).
- **썸네일**: 가로형 1200x630, 가독성 있는 텍스트 1줄 (선택).
